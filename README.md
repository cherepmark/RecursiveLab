# Рекурсивные алгоритмы: фракталы и Ханойская башня

Учебное приложение с графическим интерфейсом (Windows Forms, C# / .NET 9), демонстрирующее
рекурсию на двух классических задачах:

* **построение фракталов** — треугольник Серпинского, снежинка Коха, фрактальное дерево;
* **решение головоломки «Ханойская башня»** — классическим рекурсивным алгоритмом
  и **нерекурсивным алгоритмом с явным стеком**.

Все алгоритмы отделены от интерфейса и покрыты автоматическими тестами.

---

## 1. Цель лабораторной работы

Показать на работающем приложении:

1. как рекурсивная функция сводит задачу к задаче меньшего размера и где у неё находится базовый случай;
2. как изменение глубины рекурсии меняет детализацию результата (фракталы);
3. как рекурсивный алгоритм решает головоломку «Ханойская башня» за 2^n − 1 ходов;
4. как тот же алгоритм можно выполнить **без рекурсии**, заменив системный стек вызовов
   собственным стеком `Stack<T>` с явными кадрами, и получить ровно ту же последовательность ходов.

## 2. Возможности приложения

### Страница «Фракталы»

* выбор фрактала из списка (треугольник Серпинского, снежинка Коха, фрактальное дерево);
* настройка **глубины рекурсии** полем ввода с ограничением диапазона для каждого фрактала;
* кнопка **«Построить»** — запуск рекурсивного алгоритма и отрисовка результата на холсте;
* кнопка **«Очистить»** — сброс холста для повторного построения;
* кнопка **«Сохранить PNG»** — сохранение изображения для отчёта по лабораторной работе;
* панель результатов: число примитивов, время построения и текущее состояние;
* проверка введённых значений: недопустимая глубина даёт понятное сообщение, приложение не падает;
* автоматический пересчёт диапазона допустимой глубины при смене фрактала.

### Страница «Ханойская башня»

* выбор количества дисков (1–12) и **способа решения**: «Рекурсия» или «Явный стек»;
* три визуально различимых стержня (A, B, C) и диски разного размера с номерами;
* кнопка **«Решить»** — построение последовательности ходов выбранным алгоритмом;
* **пошаговое выполнение** кнопкой «Следующий ход» с анимацией переноса диска;
* **автоматическое воспроизведение** («Авто»/«Пауза») на таймере — интерфейс не блокируется;
* регулятор **скорости анимации** (55–1600 мс на ход);
* кнопка **«Выполнить всё»** — мгновенное доведение решения до конца;
* кнопка **«Сброс»** — возврат к начальному положению;
* индикация «Ход: X из Y», оставшееся количество ходов, теоретический минимум 2^n − 1
  и сообщение о завершении решения;
* журнал выполненных ходов в виде списка «номер. A → C (диск 1)».

### Страница «Как это работает»

Краткая теория для защиты работы: базовый случай и рекурсивный шаг, разбор каждого фрактала,
рекурсивный алгоритм Ханойской башни, доказательство T(n) = 2^n − 1 и пошаговое объяснение
замены рекурсии явным стеком.

### Принципы архитектуры

* **Бизнес-логика не знает об интерфейсе.** `RecursiveLab.Core` не ссылается на Windows Forms:
  фракталы возвращают геометрию в единичном квадрате, решатели — список ходов.
* **Единая визуализация для обоих алгоритмов.** Страница башни работает через интерфейс
  `IHanoiSolver`, поэтому переключатель «Рекурсия / Явный стек» не дублирует интерфейс.
* **Одна точка изменения модели.** Ход всегда выполняется в `HanoiState`, после чего холст
  перерисовывается, — изображение не может разойтись с состоянием алгоритма.
* **Реестры вместо ветвлений.** `FractalCatalog` и `HanoiSolverFactory` выдают алгоритм
  и границы допустимых параметров, поэтому добавление нового фрактала не требует правок в формах.
* **Отрисовка отделена от вычислений.** Холсты получают готовую геометрию/состояние и только рисуют.

## 7. Алгоритмы

### 7.1. Рекурсивное построение фракталов

Общая схема любого фрактала — функция, которая рисует элемент и вызывает себя для более мелких
элементов, пока не достигнута глубина 0:

```csharp
// RecursiveLab.Core/Fractals/SierpinskiTriangleFractal.cs
private static void Subdivide(Triangle triangle, int depth, List<Triangle> output)
{
    // --- БАЗОВЫЙ СЛУЧАЙ: глубина исчерпана, элемент добавляется целиком ---
    if (depth == 0) { output.Add(triangle); return; }

    // --- РЕКУРСИВНЫЙ ШАГ: три угловых треугольника на глубине depth - 1 ---
    Subdivide(new Triangle(triangle.A, triangle.MidAB, triangle.MidCA), depth - 1, output);
    Subdivide(new Triangle(triangle.MidCA, triangle.MidBC, triangle.C), depth - 1, output);
    Subdivide(new Triangle(triangle.MidAB, triangle.B, triangle.MidBC), depth - 1, output);
}
```

| Фрактал | Рекурсивный шаг | Базовый случай | Рост результата | Предел глубины |
|---|---|---|---|---|
| Треугольник Серпинского | деление средними линиями на 3 угловых треугольника | `depth == 0` — треугольник рисуется | 3^depth треугольников; площадь падает как (3/4)^depth | 10 |
| Снежинка Коха | сторона делится на 4 звена, на средней трети — «горб» | `depth == 0` — сторона остаётся отрезком | 3 · 4^depth отрезков; длина растёт как (4/3)^depth | 7 |
| Фрактальное дерево | из конца ветви две ветви под углом ±26°, длина × 0,72 | `depth == 0` — ветвь не делится | 2^(depth+1) − 1 ветвей | 14 |

Как это видно в коде:

* `SierpinskiTriangleFractal.Subdivide` — базовый случай `depth == 0`;
* `KochSnowflakeFractal.BuildEdge` — базовый случай `depth == 0`, рекурсивный шаг — четыре звена;
* `FractalTreeFractal.Branch` — базовый случай `depth == 0`, рекурсивный шаг — два дочерних вызова.

**Ограничение глубины.** Каждый фрактал объявляет `MaxDepth`, а `FractalAlgorithmBase.ValidateDepth`
проверяет параметр до запуска рекурсии и бросает `FractalParameterException` с допустимым
диапазоном. Интерфейс берёт диапазон из алгоритма, поэтому не может предложить недопустимое
значение, а если параметр пришёл в обход интерфейса — пользователь увидит понятное сообщение
вместо зависания или переполнения стека.

**Независимость от графики.** Геометрия собирается в список отрезков и треугольников и затем
приводится методом `FractalGeometry.FitToUnitBox()` к единичному квадрату с сохранением пропорций.
Холст лишь умножает координаты на размер области — про конкретный фрактал он ничего не знает.

### 7.2. Рекурсивное решение Ханойской башни

```csharp
// RecursiveLab.Core/Hanoi/RecursiveHanoiSolver.cs
private static void MoveTower(int count, int from, int to, int via, List<HanoiMove> moves)
{
    // --- БАЗОВЫЙ СЛУЧАЙ: один диск переносится напрямую ---
    if (count == 1) { moves.Add(new HanoiMove(from, to, 1)); return; }

    // 1) освободить самый большой диск
    MoveTower(count - 1, from, via, to, moves);
    // 2) перенести самый большой диск
    moves.Add(new HanoiMove(from, to, count));
    // 3) вернуть освобождённую башню на целевой стержень
    MoveTower(count - 1, via, to, from, moves);
}
```

Число ходов удовлетворяет равенству T(n) = 2·T(n−1) + 1, T(1) = 1, откуда **T(n) = 2^n − 1**.
Приложение показывает это значение в интерфейсе и сверяет с ним фактическое число ходов.

### 7.3. Решение через явный стек

Системный стек вызовов заменяется собственным стеком кадров — рекурсивных вызовов в коде нет:

```csharp
// RecursiveLab.Core/Hanoi/StackHanoiSolver.cs
var workStack = new Stack<Frame>();                 // Frame = (Count, From, To, Via, Expanded)
workStack.Push(new Frame(diskCount, fromPeg, toPeg, auxiliary, Expanded: false));

while (workStack.Count > 0)
{
    Frame frame = workStack.Pop();

    // Базовый случай тот же, что и в рекурсии: n == 1 — перенос без новых кадров
    if (frame.Count == 1) { moves.Add(new HanoiMove(frame.From, frame.To, 1)); continue; }

    if (!frame.Expanded)
    {
        // Кадр посещается впервые: кладём три подзадачи в обратном порядке (LIFO)
        workStack.Push(new Frame(frame.Count - 1, frame.Via, frame.To, frame.From, false)); // шаг 3
        workStack.Push(new Frame(frame.Count, frame.From, frame.To, frame.Via, true));      // шаг 2
        workStack.Push(new Frame(frame.Count - 1, frame.From, frame.Via, frame.To, false)); // шаг 1
    }
    else
    {
        moves.Add(new HanoiMove(frame.From, frame.To, frame.Count)); // перенос большого диска
    }
}
```

Порядок извлечения кадров из стека (LIFO) воспроизводит порядок рекурсивных вызовов, поэтому
последовательность ходов совпадает с рекурсивной — это проверяется тестами для 1…12 дисков.

### Что покрыто (200 тестов, все проходят)

**Фракталы**

* количество примитивов при разных глубинах (3^d, 3·4^d, 2^(d+1) − 1);
* базовые случаи: `depth = 0` даёт один треугольник / три равные стороны / один вертикальный ствол;
* геометрические законы: площадь Серпинского × (3/4)^d, рост длины Коха, длины ветвей дерева × 0,72^d;
* рост детализации при увеличении глубины, детерминированность повторного построения;
* недопустимые параметры: отрицательная глубина, глубина выше предела, абсурдно большая глубина;
* корректность геометрии: конечность координат, попадание в единичный квадрат, замкнутость ломаной Коха;
* реестр фракталов: все виды доступны, диапазоны глубины корректны, неизвестный вид отвергается.

**Ханойская башня**

* один диск — ровно один ход; количество ходов 2^n − 1 для n = 1…12;
* допустимость каждого хода и итоговое состояние (все диски на целевом стержне, порядок не нарушен);
* равенство последовательностей рекурсивного и стекового решений для 1…12 дисков;
* модель: начальное положение, правила `CanMove`, отказ при большом диске на маленьком,
  инвариант порядка дисков после каждого хода, независимость копии, сброс;
* аргументы: 0 дисков, больше технического предела, одинаковые стержни, неверный индекс;
* «судья» решения: ловит нарушение порядка, отсутствие диска, незавершённое и неоптимальное решение;
* **отсутствие рекурсии в стековом решателе проверяется на уровне IL-кода**
  (`tests/RecursiveLab.Core.Tests/IlRecursionInspector.cs`): в методе `Solve` нет вызова самого себя,
  зато есть создание `System.Collections.Generic.Stack<T>`; для контроля тот же анализатор обязан
  найти рекурсивный вызов в `RecursiveHanoiSolver`.

**Интерфейс** — встроенная самопроверка `--smoke` (66 проверок):

* окно открывается, вкладки и холсты создаются, снимок окна сохраняется;
* для каждого фрактала: выбор в списке, диапазон глубины, построение, число примитивов,
  отказ при недопустимой глубине, очистка холста, рост детализации;
* анализ изображения: непустая отрисовка, центр тяжести фигуры в центре холста,
  баланс левой и правой половин (симметрия фракталов);
* для обоих решателей: подготовка решения, начальное положение, пошаговое выполнение,
  завершение анимации хода по таймеру, полное решение, индикация завершения,

* по изображению проверяется, что диски находятся на исходном (центр тяжести слева)
  и на целевом (центр тяжести справа) стержне;
* автоматическое воспроизведение на таймере доигрывает решение до конца и корректно снимает паузу.

## 9. Ограничения и известные особенности

* приложение работает только в Windows (Windows Forms);
* глубина рекурсии ограничена для каждого фрактала: на предельных значениях отдельные элементы
  становятся меньше пикселя, поэтому дальнейший рост глубины уже не улучшает картинку;
* количество дисков в интерфейсе ограничено 12 (4095 ходов): этого достаточно для демонстрации,
  а более длинные решения неудобно смотреть глазами; ядро алгоритмов поддерживает до 20 дисков;
* в автоматическом режиме интерфейс не блокируется (таймер WinForms), но при минимальной задержке
  (55 мс) анимация каждого хода сокращается до ~70 мс;
* изображение соответствует состоянию модели в любой момент, кроме кадров анимации переноса:
  ход применяется к модели по завершении анимации, а летящий диск рисуется отдельно.
